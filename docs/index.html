flexsearch-dx

A type-safe FlexibleSearch DSL and performance analyzer for SAP Commerce — queries that fail at compile time, not in production.

View on GitHub Why it's useful

The problem

FlexibleSearch is stringly-typed: queries break silently when the model changes, and hide N+1 and missing-index performance cliffs. Generic SQL tools don't understand the type-system→table mapping or the region cache.

Expertise-gated

Costly & slow

Manual, error-prone work that scales badly across a large estate.

Under-tooled

The ecosystem lacks modern, opinionated backend tooling for this.

The solution & why it's useful

(a) A **type-safe query builder** generated from the type model so queries fail at compile time; (b) a **query analyzer** that explains plans, flags N+1 and cache-hostile patterns, and suggests indexes — SAP-Commerce-aware.

Compile-time safety

Queries are built from generated, type-checked metamodel classes — a renamed attribute is a build error, not a 2am incident.

Fluent & readable

A jOOQ-style builder that reads like the query it produces.

Performance-aware

The analyzer knows the type→table mapping and flags N+1, full scans and cache-hostile access.

Zero runtime surprises

What compiles is what runs.

Usage example

Distilled from the runnable tutorial examples/Example.java. The Output block is real captured stdout.

Build a type-checked FlexibleSearch string, then lint it for performance foot-guns:

TypeModel model = TypeModel.builder()
        .type("Product", "code", "name", "catalogVersion", "creationtime")
        .type("Currency", "isocode", "name", "active", "conversion")
        .build();

String q = QueryBuilder.from(model, "Product", "p")
        .select("code", "name", "creationtime")
        .where("catalogVersion", "=", "cv")
        .where("name", "LIKE", "namePattern")
        .orderBy("creationtime", false) // DESC
        .orderBy("code", true)          // ASC
        .build();

// A typo fails fast, at build time:
QueryBuilder.from(model, "Product", "p").select("code", "nam").build();

// Lint an unbounded query:
QueryAnalyzer.analyze("SELECT {p:code} FROM {Product AS p}");
Output:
SELECT {p:code}, {p:name}, {p:creationtime} FROM {Product AS p} WHERE {p:catalogVersion} = ?cv AND {p:name} LIKE ?namePattern ORDER BY {p:creationtime} DESC, {p:code} ASC

Rejected as expected: unknown attribute 'nam' on Product

WARN: No WHERE clause; this query performs a full table scan.

Run it yourself (JDK 21, no Gradle): find src/main/java -name '*.java' | xargs javac -d /tmp/ex-flex && java -cp /tmp/ex-flex com.sapcommercetools.flexsearch.examples.Example
